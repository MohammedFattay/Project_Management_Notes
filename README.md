# موقع «إدارة المشاريع البرمجية»

نشرٌ ثابت لمجلد `Project Management` من فولت أوبسيديان، مبنيٌّ على [Quartz v5](https://quartz.jzhao.xyz/).

## البنية

هذا المستودع **منفصل** عن الفولت عمدًا:

| المسار                      | ما هو                                               |
| --------------------------- | --------------------------------------------------- |
| `D:\Obsidian_Vault`         | الفولت الخاص — لا يُنشر منه إلا مجلد واحد           |
| `D:\quartz-site`            | هذا المستودع، عام                                   |
| `content/`                  | **نسخة مولَّدة** — لا تُحرَّر هنا، فالمزامنة تمحوها |
| `site-files/`               | ملفات تخصّ الموقع لا الفولت (الصفحة الرئيسية)       |
| `quartz.config.yaml`        | الإعداد: اللغة، الخطوط، الإضافات                    |
| `quartz/styles/custom.scss` | تحسينات العربية (RTL، الخطوط داخل المعادلات)        |
| `sync.ps1`                  | المزامنة والبناء والنشر                             |
| `check-custom.ps1`          | يتحقّق أنّ تخصيصات المستودع ما تزال قائمة           |

**تُكتب الملاحظات في أوبسيديان دائمًا، لا في `content/`.**

## الاستعمال

```powershell
.\sync.ps1                    # نسخ المحتوى من الفولت
.\sync.ps1 -Serve             # نسخ ثم معاينة على http://localhost:8080
.\sync.ps1 -Push              # نشر — يدفع إلى المستودعين معًا
.\sync.ps1 -Push -SiteOnly    # الموقع وحده، للإصلاحات الخاصّة بالنشر
.\check-custom.ps1            # فحص التخصيصات — بعد كل سحب من upstream
```

و`-Push` يشغّل `check-custom.ps1` بنفسه قبل الدفع، فلا يُنشر ما سقط منه تخصيص.

الدفع إلى `main` يُشغّل `.github/workflows/deploy.yaml`، فيبني الموقع وينشره على GitHub Pages في نحو ثلاث دقائق ونصف.

### وجهة الدفع تُقرَّر بطبيعة الإصلاح

`-Push` يدفع إلى **الاثنين** لأن مصدر المحتوى هو الفولت لا `content/`؛ فلو دُفع الموقع وحده لصارت النسخة العامة أحدث من الخاصة. و`-SiteOnly` لِما لا يخصّ الفولت أصلًا.

**والمعيار عمليّ:** أيظهر هذا الخلل لو أُغلق المتصفّح وفُتح أوبسيديان؟

|                 | مثال مقيس                                                                                  | الوجهة  |
| --------------- | ------------------------------------------------------------------------------------------ | ------- |
| **عامّ**        | تسميات `quadrantChart` غير المنصَّصة — `window.mermaid.parse` في أوبسيديان يعطي الخطأ نفسه | الاثنان |
| **خاصّ بالنشر** | ألوان `hsl(calc(…))` من ثيم Quartz التي كانت تُسقط كل المخططات                             | الموقع  |
| **خاصّ بالنشر** | روابط تشير إلى مجلدات لم تُنشر — تعمل كلها في الفولت                                       | الموقع  |

وتفصيلها في القاعدة 15 من `CLAUDE.md` في الفولت.

## ما خُصِّص لهذا المستودع

- `locale: ar-SA` — يضبط `<html lang="ar" dir="rtl">` ويعرّب واجهة الموقع.
- **الخطوط:** Tajawal للعناوين وIBM Plex Sans Arabic للنصّ. وتُضبط في **موضعين**: `configuration.theme.typography` وخيارات إضافة `quartz-fonts` — فالإضافة لا تقرأ الأولى، وتركها فارغةً يُعيد خطوطًا بلا حروف عربية.
- `analytics: null` — معطّلة، فتفعيلها يرسل بيانات الزوّار إلى طرف ثالث.
- `ignorePatterns` — تستثني ملفات القوالب (`_*Template*`) دون ما يبدأ بشرطة سفلية من المحتوى الحقيقي.
- حُذفت سيور عمل Quartz الخاصة بمستودعها، وبقي `deploy.yaml` وحده.
- **إضافة `excalidraw` معطّلة** — حزمتها غير منشورة على npm، فكانت تُنذر في كل بناء بلا فائدة.

### `tsconfig.json`: ترحيل عن `moduleResolution: node10`

Quartz الأصلي يستعمل `"node"` (أي `node10`)، وهي مهجورة و**تتوقّف عن العمل في TypeScript 7**. وقد رُحِّلت هنا إلى `"bundler"` — وهي الصحيحة لحزمة ESM تُبنى بـ esbuild لا بـ tsc.

وهذا **ليس ترحيلًا بلا كلفة**: `bundler` تحترم خرائط `exports` التي كانت `node10` تتجاوزها، فظهرت حزمتان لا تُصدّران ما يستورده Quartz منهما. وعولجتا بتعيين صريح في `paths`:

| الحزمة             | العلّة                                      |
| ------------------ | ------------------------------------------- |
| `micromorph`       | تشحن `index.d.ts` ولا تعلن عنه في `exports` |
| `remark-parse/lib` | استيراد عميق غير معلَن في `exports`         |

وأُضيف `precheck` إلى `package.json` يولّد `.quartz/plugins` قبل `tsc`. فالوحدة مولَّدة ومستثناة من git، وتغيب في أي استنساخ جديد فيفشل الفحص بخطأ وحدة مفقودة. (`prebuild` الموجود في Quartz معلَّق بسكربت `build` لا وجود له، فلا يعمل أبدًا.)

و`content` و`.quartz` أُضيفا إلى `.prettierignore`: الأول نسخة مولَّدة من الفولت — تنسيقه يعارض المصدر وتمحوه أول مزامنة.

**النتيجة:** `npm run check` يمرّ نظيفًا (`tsc` + Prettier)، ولا تحذير هجران في المحرِّر مهما كانت نسخة TypeScript فيه. وهذه الملفات تنحرف عن Quartz الأصلي، وحراستها في القسم التالي.

## التحديث من `upstream`

فرعٌ من مشروع مفتوح لا بدّ أن ينحرف عنه، والمشكلة ليست في الانحراف بل في أن **يُنسى**: فيُسحب تحديث، فيعود ملفٌّ إلى أصله، فيبني الموقع بنجاح ويخرج مكسورًا — وكلّ علامة ظاهرة تقول إنّ الأمر تمّ. والتوثيق وحده لا يحرس من هذا، لأنّه يشترط أن يتذكّر أحدٌ أن يقرأه. فالحراسة هنا بثلاثة أشياء، لا بواحد.

### ١. تاريخٌ موصول، فالتحديث دمجٌ لا نسخٌ يدويّ

كان تاريخ هذا المستودع **جذرًا يتيمًا** لا صلة له بـ Quartz — أثرًا لإنشائه بفرع `orphan` — فكان `git merge upstream/v5` يرفض العمل لانعدام أصل مشترك، ولا يبقى إلّا نقل التغييرات باليد ملفًّا ملفًّا. وقد وُصل التاريخ بدمجٍ واحد باستراتيجية `ours`: يُنشئ الأصل المشترك ولا يمسّ شجرة الملفات، لأنّ شجرتنا **هي** شجرة `upstream/v5` مضافًا إليها تخصيصاتنا.

**وأثره مُقيس لا مُفترَض.** حُوكي إصدارٌ من upstream يمسّ ثلاثة ملفات، فكانت النتيجة:

| الملفّ في الإصدار الوهميّ | النتيجة |
| ------------------------- | -------------------------------- |
| `tsconfig.json`           | تعارض — ونحن نخصّصه، فمتوقَّع |
| `.prettierignore`         | تعارض — ونحن نخصّصه، فمتوقَّع |
| `quartz/styles/base.scss` | **دُمج تلقائيًّا** |

ولم تُبعَث سيور العمل المحذوفة، ولم يمسّ الدمجُ الـ150 ملفًّا الأخرى. وحجم التعارض في `tsconfig.json` كتلة واحدة.

> **ولزمه أن يكون التاريخ كاملًا.** كان الاستنساخ سطحيًّا (`shallow`)، فرفض البعيد الدفع بـ `did not receive expected object`: يستحيل دفع دمجٍ أبوه الثاني بلا سلف. وحُلّ بـ `git fetch --unshallow upstream` — 39 ميغابايت من تاريخ Quartz. فلا يُستنسخ هذا المستودع بـ `--depth` بعد اليوم.

### ٢. سطح التخصيص صغير ومعروف

الفرق بين هذا المستودع و`upstream/v5` — بعد استثناء ما أضفناه ولا وجود له عنده (`content/` · `site-files/` · `quartz.config.yaml` · `sync.ps1` · هذا الملف) — هو:

| الملف | التخصيص | كم مسّه upstream في تاريخ v5 كلّه؟ |
| --------------------------- | -------------------------------------- | ---------------------------------- |
| `quartz/styles/custom.scss` | تثبيت ألوان Mermaid + قواعد العربية | تثبيت واحد (وهو **ملفّ المستخدم** أصلًا) |
| `tsconfig.json`             | `bundler` + تعيينات `paths` | تثبيت واحد |
| `package.json`              | `precheck` + `allowScripts` | تثبيت واحد |
| `.prettierignore`           | استثناء `content` و`.quartz` | تثبيت واحد |
| `.github/workflows/`        | حُذفت سيور Quartz، وبقي `deploy.yaml` | — |

**وأكثر «تحديثات» Quartz v5 لا تمسّ هذه أصلًا:** فالإضافات صارت حزم npm مستقلّة (`@quartz-community/*`)، وترقيتها `npm update` تغيّر `package-lock.json` وحده. وما يستدعي دمجًا من upstream هو تغيّر هيكل Quartz نفسه، وهو نادر.

### ٣. فحصٌ يقول ما سقط

`check-custom.ps1` يفحص **17 تخصيصًا** ويخرج بالرمز 1 إن سقط أحدها، ويذكر مع كلّ سقوط **ماذا ينكسر بسببه** لا اسمه فقط. وهو يفحص الإعداد والأنماط وسلسلة الأدوات وسيور العمل، ثم **الناتج المبنيّ نفسه** (وجود `dir="rtl"` في `public/index.html`) — فقد يكون الإعداد سليمًا والناتج مكسورًا.

ويُشغّله `sync.ps1 -Push` تلقائيًّا بعد البناء وقبل الدفع، فلا يعتمد على التذكّر.

### الإجراء

```powershell
git fetch upstream
git merge upstream/v5      # التعارض محصور في جدول «سطح التخصيص» أعلاه
npm install
npm run check              # tsc + Prettier
.\check-custom.ps1         # ما الذي أعاده الدمج إلى أصله؟
.\sync.ps1 -Serve          # معاينة بالعين قبل النشر
.\sync.ps1 -Push -SiteOnly # ترقية Quartz لا تخصّ الفولت
```

**وعند تعارضٍ في أحد ملفات الجدول:** لا يُختار طرفٌ كاملًا. فالمطلوب تغييرنا **فوق** تغيير upstream — سطر `moduleResolution` منّا، وما أضافه upstream حوله يبقى. والفحص هو ما يقول إن أخطأت.
