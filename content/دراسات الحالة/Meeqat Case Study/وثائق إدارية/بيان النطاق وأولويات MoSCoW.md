# 📐 بيان النطاق وأولويات MoSCoW

> [!info] الغرض
> إنشاء **خط أساس للنطاق** ([[Baseline]]) بعد أن تراكمت الميزات بلا خطّة محدَّثة — ليصبح لدينا مرجع نقيس عليه أي طلب قادم.

---

## 1) بيان النطاق

> [!success] داخل النطاق (النسخة 1.0)

| المجال | التفصيل |
| --- | --- |
| الجهات والمستخدمون | إنشاء الجهات · دعوة الموظّفين · أربعة أدوار · عزل تامّ |
| الفعاليات | بيانات مترجَمة · أيام · مناطق · نافذة تسجيل · هوية بصرية · صفحة هبوط |
| التسجيل | نموذج ديناميكي · منع تكرار · تذكرة QR · بطاقة دخول · استيراد جماعي |
| الحضور | ماسح متصفّح · دخول/خروج بالمناطق · بحث يدوي · إغلاق تلقائي · حساب المدّة |
| التواصل | تذكيرات مجدولة ويدوية · قوالب رسائل · تأكيدات · دعوات تقييم |
| النماذج | محرّك نماذج بأقسام وأسئلة ومنطق ظهور · قوائم خيارات · نتائج |
| الشهادات | إصدار مشروط · قالب مخصّص · إصدار جماعي · رابط تحقّق عام |
| الخدمة الذاتية | دخول برمز مؤقّت · تعديل بيانات · سجل تعديلات |
| التحليلات | مؤشرات الفعالية والمناطق والجهة · تصدير |
| العرضي | عربي/إنجليزي واتجاه تلقائي · صفحات أخطاء · نسخ احتياطي |

> [!failure] خارج النطاق صراحةً

| البند | سبب الاستبعاد |
| --- | --- |
| بيع التذاكر والدفع الإلكتروني | يفتح مخاطر مالية وتنظيمية غير مبرَّرة الآن |
| تطبيق جوّال أصلي | الماسح داخل المتصفّح يكفي |
| بثّ مباشر / فعاليات افتراضية | سوق مختلف وتكلفة تشغيل عالية |
| تكامل مع أنظمة اعتماد مهني | يحتاج شراكات وعقودًا |
| تطبيق مورّدين وخدمات لوجستية | خارج تعريف المنتج |
| تقارير مخصّصة لكل جهة | يهدم منطق المنتج الموحّد |

> [!warning] قاعدة التعامل مع «خارج النطاق»
> الطلب لا يُرفض شخصيًّا — بل **يُقارَن بهذه الوثيقة**. وإن أُقرّ دخوله، فبتحديث هذه الوثيقة وخارطة الطريق معًا، لا بإضافته صامتًا.

## 2) أولويات MoSCoW

| الأولوية | البنود |
| --- | --- |
| **يجب (Must)** | التسجيل · منع التكرار · تذكرة QR · المسح · الشهادة المشروطة · التحقّق · عزل الجهات · الأدوار |
| **ينبغي (Should)** | التذكيرات · المناطق · الإغلاق التلقائي · التحليلات · قوالب الرسائل · التصدير · الاستيراد |
| **يمكن (Could)** | مصمّم قالب الشهادة · بطاقة الدخول · الخدمة الذاتية · الإصدار الجماعي · مبدّل اللغة · صفحات أخطاء مخصّصة |
| **لن (Won't الآن)** | كل بنود «خارج النطاق» أعلاه |

> [!note] قاعدة الحجم
> يجب ألّا يتجاوز صفّ **يجب** ~60% من طاقة الموجة، وإلا فلا مجال للمناورة عند أول مفاجأة.

## 3) مصفوفة التتبّع (متطلّب ← تصميم ← اختبار)

| المتطلّب | معيار القبول | وثيقة التصميم | تغطية اختبار |
| --- | --- | --- | --- |
| منع التسجيل المكرّر | AC-1 | تصميم شريحة التسجيل | ✅ آلي |
| وصول التذكرة خلال دقيقة | AC-2 | تصميم شريحة التسجيل | ⚠️ يدوي فقط |
| المسح يرفض التكرار | AC-3 | تصميم الماسح + المناطق | ✅ آلي |
| تعدّد اللغات والاتجاه | AC-4 | عرضي | ⚠️ يدوي فقط |
| شهادة بعد حضور وتقييم | AC-5 | تصميم التقييم والشهادة | ✅ آلي |
| مطابقة لوحة التحاليل | AC-6 | تصميم التحاليل | ⚠️ جزئي |
| التصدير | AC-7 | تصميم التحاليل | ⚠️ يدوي فقط |
| صيغة رقم التصنيف | AC-8 | تصميم التسجيل | ✅ آلي |

> [!danger] ما تكشفه المصفوفة
> **أربعة من ثمانية معايير** لا تغطّيها اختبارات آلية. هذا يعني أن أي تعديل مستقبلي قد يكسرها بصمت — وهذه أوضح فجوة قابلة للإغلاق بجهد محدود.
