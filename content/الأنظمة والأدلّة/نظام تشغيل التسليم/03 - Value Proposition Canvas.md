# Value Proposition Canvas — القالب التشغيلي

## لماذا هذا القالب موجود؟

> [!quote] من الوثيقة التفسيرية
> نستخدمه حتى لا يتحوّل المشروع إلى **تنفيذ موديولات بلا أثر**. المشروع الحقيقي ليس `Odoo`، بل تحسين التدفّق التشغيلي والمالي.

> [!success] القاعدة الذهبية
> **العميل لا يشتري `Odoo`. العميل يشتري تقليل التأخير، وتقليل الأخطاء، وتحسين السيطرة.**

للشرح النظري الكامل للأداة (المهام الوظيفية/الاجتماعية/العاطفية، والآلام قبل/أثناء/بعد، والمكاسب المطلوبة/المتوقّعة/غير المتوقّعة) انظر [[Value Proposition Canvas]] و [[01 - من إدارة المهام إلى قيادة التسليم]]. هذه الملاحظة هي **القالب التشغيلي المختصر** المستخدم في ملف الـ Excel.

## القالب مملوءاً — [[حالة النور للتوزيع]]

### `Customer Jobs`

| النوع | الوظيفة |
|---|---|
| `Functional` | تسريع تنفيذ الطلبات |
| `Functional` | تحسين دقة المخزون |
| `Functional` | تقليل أخطاء الفواتير |
| `Functional` | تسريع التقارير المالية |
| `Emotional` | تقليل الضغط التشغيلي |
| `Emotional` | رفع الثقة في البيانات |
| `Social` | تقديم تقارير احترافية للإدارة |

### `Customer Pains`

| المشكلة | الأثر |
|---|---|
| تأخّر الطلبات | فقدان عملاء |
| فروق المخزون | نقص المنتجات |
| أخطاء الفواتير | نزاعات مالية |
| التقارير اليدوية | قرارات بطيئة |
| الاعتمادات اليدوية | `Bottlenecks` |
| اختلاف البيانات | فقدان السيطرة |

### `Customer Gains`

| المكسب | القيمة |
|---|---|
| طلبات أسرع | رضا العملاء |
| دقة مخزون أعلى | تقليل الهدر |
| تقارير فورية | قرارات أسرع |
| `Workflow` موحّد | استقرار تشغيلي |
| تقليل العمل اليدوي | رفع الكفاءة |

### `Pain Relievers`

| المشكلة | الحلّ |
|---|---|
| تأخّر الاعتمادات | `Approval Workflow` |
| فروق المخزون | `Barcode` + `Cycle Count` |
| أخطاء الفواتير | `Validation Rules` |
| التقارير اليدوية | `Dashboards` |
| تأخّر المطابقة | `Bank Integration` |

| المكسب | الحلّ |
|---|---|

## كيف تقرأ اللوحة — «ما بين السطور»

> [!tip] إضافة 1 — أهمّ عمود هو «الأثر» لا «المشكلة»
> «تأخّر الطلبات» جملة لا تُحرّك أحداً. «**فقدان عملاء**» جملة تُحرّك `COO`. عمود الأثر هو الجسر إلى [[07 - Financial Loss Analysis]] — وبدونه تبقى اللوحة وثيقة تحليل لا وثيقة إقناع.

> [!tip] إضافة 2 — لاحظ آخر صفّ في `Gain Creators`
> «تبنٍّ أعلى ← `Structured Training` + `Hypercare`». هذا الصفّ **ليس ميزة في النظام** — إنه ممارسة تسليم. ووجوده داخل خريطة القيمة يقول شيئاً مهماً: **جزء من القيمة يُنتَج بطريقة التسليم لا بالبرمجة**. وهو ما يجعل [[21 - UAT Management]] و[[23 - Hypercare & SLA]] عناصر قيمة لا عناصر تكلفة.

> [!warning] الفخّ الشائع — `Pain Reliever` بلا `Pain`
> في المحاضرة الأولى مثال شهير: «تطبيق مقترح الإجازة بالذكاء الاصطناعي» — لا يقابله أي ألم، ولا يحقّق أي مكسب مطلوب، ولا يساعد على إنجاز أي مهمة. النتيجة: **لا `FIT`**.
> القاعدة العملية: **كل عنصر في `Value Map` يجب أن يشير إلى صفّ محدّد في `Customer Profile`. العنصر اليتيم يُحذف.**
